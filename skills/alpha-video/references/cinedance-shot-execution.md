# CINEDANCE 单镜头执行层融合协议

本文件把 `cinedance` Skill 的单镜头导演能力接入 `Alpha-Filmos-video`。它位于项目级战斗设计、平台 B 稿和 FilmOS Video 生成之间：前者决定为什么打、谁先动、接触与状态如何连续；本层把一个已确认的 beat 封装成可执行的 CINEDANCE 当前镜头。它不替代多回合路线、动作性能预检、平台画像或 `acting` 表演层。

## 何时启用

以下任一情况出现时读取本文件：

- 用户明确说 `cinedance`、CINEDANCE、单镜头导演、连续长镜头或 FilmOS Video 镜头 Prompt；
- 用户需要把一个已确认 beat 转成空间、摄影、时间、物理、灯光、声音和连续性完整的单镜执行稿；
- 用户明确要求生成 FilmOS 视频，需要把当前 beat 封装为 CINEDANCE 风格 Prompt；
- 需要修复已生成镜头的首帧地理、动作顺序、路径/受力、摄影或连续性问题。

仅要项目级战斗设计、路线、分镜或平台 B 稿时，不自动生成 CINEDANCE 长提示词；只在交付物需要单镜执行时启用。

## 职责分层

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `Alpha-Filmos-video` | 多回合结构、战斗目标、路线、攻防因果、平台编译、负载审计 | 把所有项目强制变成单镜头 |
| `acting` | 目标、阻碍、策略、眼神、呼吸、重心、身体事务、对白和受击后的可观察变化 | 命中、受力、空间或摄影机因果 |
| `cinedance` | 当前镜头的参考职责、首帧、空间阻挡、镜头、时间、物理、灯光、声音和连续性 | 重写用户锁定的胜负、动作顺序或平台边界 |
| FilmOS Video | 选择当前可用模型、一次提交、轮询和下载实际结果 | 由普通 Prompt 设计自动触发付费任务 |

## Beat 到 CINEDANCE 的编译

先冻结一个已通过动作性能预检的 beat；不要把整段多回合战斗直接塞进一个单镜。按以下顺序编译，只保留当前镜头需要的区块：

1. **Active reference mapping**：每张人物、场景、武器、视频、音频、首帧、尾帧或走位参考只分配一个职责；排除路线图箭头、坐标、图例、UI 和过期参考。
2. **One-sentence brief**：主体 + 地点 + 当前事件 + 视觉模式 + 核心镜头行为；这是摘要，不替代空间或时间字段。
3. **Scene context**：只写本镜发生的事件、目标和结果，不携带上一镜的叙述残留。
4. **Location map**：从摄影机方向定义 screen-left/right，写前景/中景/后景、地标、角色位置、移动路径和光线方向。
5. **First frame and spatial blocking**：首帧必须说明已在画面中的主体、距离、身体朝向、躯干方向与眼睛目标；需要建立地理时，不留无因空镜。
6. **Format mode**：默认 `SINGLE CONTINUOUS TAKE`；只有用户要求剪辑或动作性能确实超载时才使用多镜，并逐镜写清切点。
7. **Optics and camera**：写可观察的视场、摄影机距离/高度/侧别、运动、焦点、构图和景深；不把镜头品牌、光圈或精确帧率写成平台保证。
8. **Action timing**：把 beat 的时间意图写成无空缺的连续区间，每段同时写发生什么、为什么发生和结束状态；每段只保留一个主要攻击、防守或能力事件。
9. **Physics**：写重量、接触、惯性、摩擦、衣发/液体/粒子行为、受力方向、材料响应和落定状态；动作格式保持“起始状态 → 动作/方向/速度 → 目标/接触 → 结果 → 结束状态”。
10. **Lighting / Audio**：灯光写来源、方向、摄影机侧和曝光优先级；声音只保留用户提供或已确认的对白、环境、音效和音乐规则，并与身体事件同步。
11. **Continuity locks**：锁定身份、服装、武器、伤势、屏幕方向、光线方向、声音状态、acting 情绪惯性和必需的最终状态。
12. **Local positive locks**：只加入本镜为防止已知失败所需的正向约束；负面约束保持短小，不复制整套负面词库。

## 表演层与单镜封装

如果本 beat 启用了 `acting`，把以下 cue 放入 CINEDANCE 的首帧、动作时间、对白和连续性区块：

- `objective / obstacle_stakes / tactic`：说明角色此刻要改变什么、被什么挡住、正在采用什么策略；
- `gaze_target`：眼睛目标、搜索/锁定/重新确认的顺序，躯干方向与眼睛方向分开写；
- `body_state / business`：重心、呼吸、握持、肩颈、步伐补偿和与目标相关的身体事务；
- `performance_beats`：2–4 个可见变化，不写空泛情绪标签；
- `hit_reaction / next_action`：受击方向、重量转移、落定状态和由此触发的格挡、撤退、换位、能力切换或反制；
- `voice_dialogue`：只粘贴用户提供的对白；非说话角色保持闭唇，不添加旁白、字幕或即兴台词。

表演 cue 不能替代动作接触、敌方威胁、受力或镜头落点。特写结束后，必须重新锚定人物、武器、空间、受力方向或战场优势，并把新的 `end_state` 交给下一 beat。

## 冲突裁决与 FilmOS 边界

冲突优先级为：`user_constraints > immutable_facts > platform_hard_limits > motion_state_chain > cinedance_spatial_controls > acting_decoration`。CINEDANCE 的默认一镜到底不能覆盖用户明确要求的剪辑，也不能把多个独立主动作隐藏在同一时间段；动作过密时拆镜或使用合适的运动/走位参考。

Prompt-only 请求只交付封装后的英文 CINEDANCE 当前镜头 Prompt，不提交任务。只有用户明确要求生成视频时，才遵循独立 `cinedance` Skill 的 FilmOS 流程：先读取实时模型目录，选择兼容模型，调用一次创建，记录任务与计费状态，轮询同一任务，完成后只下载一次；不使用 shell、curl、Python、provider-specific 路由、临时 URL 或其他视频提供方，也不因超时或歧义自动重试。

## 交付前检查

- 当前镜头只有一个主要事件、一个主运镜和一个明确落点；
- 首帧已建立所需地理，screen-left/right 从摄影机方向定义；
- 时间区间无空缺，包含开始状态、路径/受力、接触结果和结束状态；
- 物理、灯光、声音和连续性与动作链一致；
- 启用 `acting` 时，目标、视线、身体状态、受击后果和下一动作均可观察；
- 没有残留角色、过期参考、上一镜措辞、无因空镜或把情绪/镜头运动当作动作结果；
- 需要生成视频时，未绕过 FilmOS 的实时模型与一次提交边界。
