# 高燃动作性能合同

本合同把“超燃、快速、不要笨重、不要穿帮”转成生成前可以审计的动作状态。数字只作为 Skill 的设计报警线，不是视频模型的帧级执行保证。

## 1. 项目合同

高速约 15 秒项目默认满足：

- 开场只允许极短角色读取，早段必须出现主动威胁、闪避、格挡或首次接触；
- 有效攻防覆盖主体时长，纯对峙、长蓄力、胜者摆姿和淡出不得吞掉主要动作预算；
- 双方至少各有一次主动选择和一次有效应对；
- 至少一次优势、距离、位置、武器/能力或环境状态变化；
- 主要局部子弹时间默认最多一个，绑定单一接触/闪避/反转/终局，随后立即恢复实时高速并接回下一动作；
- 结尾短促，最后状态仍保留追击、瞄准、再激活、新威胁或明确受力余势。

若平台、题材或用户要求仪式感/恐怖迟疑/克制写实，可以偏离运动密度，但每段等待仍必须改变威胁、信息或距离。

## 2. Beat 状态合同

每个动作 beat 使用以下字段：

```json
{
  "id": "beat-1",
  "scene_id": "stone-courtyard",
  "duration_sec": 1.2,
  "contact_offset_sec": 0.6,
  "idle_after_sec": 0.1,
  "start_state": "人物、武器、方向、距离、场景状态",
  "lead_action": "当前唯一主导攻击/变招/追击",
  "response": "对方的格挡、闪避、卸力或反击",
  "contact": "明确部位、武器或能力接触",
  "result": "受力、位移、状态或优势变化",
  "end_state": "下一 beat 必须继承的可见状态",
  "active_subjects": ["A", "B"],
  "micro_actions": ["起手", "应对", "变招"],
  "camera": {
    "operators": ["一个主运镜"],
    "trigger": "触发摄影变化的动作事件",
    "focus": "单一视觉重点",
    "landing": "摄影机落点与重锚"
  },
  "vfx_systems": [
    {
      "description": "刀枪接触火星",
      "role": "contact_feedback",
      "priority": 100,
      "causal_binding": "刀刃撞上枪杆"
    }
  ],
  "transition": "动作方向匹配切入下一节拍",
  "bullet_time": {
    "enabled": false
  }
}
```

相邻 beat 必须满足 `beat[n].end_state == beat[n+1].start_state`。如果设计语言需要更丰富的状态对象，可以先规范化为同一字符串或稳定 ID 后再编译；不能用“衔接自然”替代真实状态继承。

`duration_sec` 记录当前有效动作节拍占用的导演时间，`contact_offset_sec` 记录本 beat 内首次接触相对 beat 起点的位置，`idle_after_sec` 记录该节拍后没有新攻击、应对、追击、接触或优势变化的间隔。约 15 秒高速项目的有效 beat 时长合计应覆盖总时长约 75% 以上，10 秒以上高速项目默认至少 5 个可辨认 beat，单次空档不得超过约 1.2 秒；首个可见接触/有效应对默认在约 1.5 秒内。偏离时改用非高速模式或说明平台/题材原因。

## 3. 项目级高燃映射

所有完整项目只要写入全局高燃固定块，就必须提供；高速项目分布到主体时长，慢节奏/克制项目集中到少数关键接触：

```json
{
  "high_energy_map": {
    "high_speed_follow": "beat-1",
    "controlled_orbit": "beat-3",
    "push_or_pull": "beat-4",
    "bullet_time": "beat-2",
    "action_driven_cut": "beat-1",
    "same_scene_chain": ["beat-1", "beat-2", "beat-3"],
    "dense_impacts": ["beat-1", "beat-2", "beat-3"]
  }
}
```

映射必须与 beat 的真实 `camera.operators / bullet_time / transition / contact` 对应。缺字段、引用不存在的 beat，或把 `bullet_time` 指向未启用子弹时间的 beat，均属于硬错误。

## 4. 复杂度预算

通用保守预算：

- 每 beat 1 个前景主动作；
- 最多 1 个支援结果；
- 最多 1 个主运镜；
- 2–4 个前后相连的微动作；
- 通常最多 2 个活动主体和 1–2 套独立 VFX；
- 摄影机移动必须有触发、焦点和落点。

平台画像可以调整主体、动作和参考容量，但不能放宽“单主运镜、明确接触、结束状态可继承”三项。

## 5. 硬错误与警告

硬错误：

- 缺起始/结束状态、攻击、应对、接触或结果；
- 相邻状态断裂；
- 单 beat 出现多个主运镜；
- 子弹时间缺触发或缺恢复动作；
- 时长/画幅超出已确认的平台硬边界。
- 输入模式或参考数量超过平台已确认能力；
- 高燃固定块缺项目级 beat 映射或映射与实际运镜/子弹时间/转场不一致。
- 活动主体或微动作超过平台策略预算；这两类超载不能靠截断名单修复，必须重写成主动作+支援结果或拆 beat。

警告/可自动降级项：

- VFX 超过平台策略预算；只有每项都带 `description / role / priority / causal_binding` 时，编译器才可优先保留接触反馈、状态变化、环境后果和连续锚点，并在 `applied_downgrades` 记录保留/删除项；无结构 VFX 超预算属于硬错误，禁止按输入顺序盲切；
- 高速短片有多个主要子弹时间；
- 高速项目缺双方主动选择、优势变化或早段接触；
- 正向动作与负面约束互相抵消。

有硬错误时不得称为最终 B 稿。警告必须在 A→B 编译时降负或向用户明确保留的风险。

## 6. 降负顺序

`装饰插镜 → 背景独立事件 → 并发 VFX → 摄影复杂度 → 自然动作转折处拆镜`

确定性编译器只自动裁减可安全识别的并发 VFX；活动主体、微动作、主运镜和动作因果超载必须返回硬错误，由导演层重写。不得先删除攻击—应对—接触—结果链，也不得把 3–4 秒复杂动作简单拉长成慢速展示。拆镜后用结束状态、动作方向、武器位置、场景破坏和遮挡/擦镜锚点继续下一段。
