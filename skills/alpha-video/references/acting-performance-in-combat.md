# 战斗表演层：ACTING 与 Alpha-Filmos-video 融合协议

本文件把 `acting` Skill 的可观察角色表演方法接入 `Alpha-Filmos-video`。它是战斗设计的表演层，不替代动作因果、空间路线、摄影机、平台画像或动作性能预检，也不把情绪词当作可执行结果。

## 何时启用

以下任一情况出现时读取本文件：

- 用户要求角色魅力、关系张力、情绪、对白、微表演或受击表现；
- 需要近景攻防、高手对决、守护、反转、Boss 弱点窗口或角色 PV；
- 角色的判断、恐惧、疼痛、保护、羞辱、决绝或犹豫必须改变下一步战术；
- 用户明确要求生成视频，需要把表演层和完整镜头 Prompt 组合。

纯动作展示且没有角色判断、关系或受击变化时，表演层可保持最小化，只写起始状态、视线目标、呼吸/重心和结果后的状态承接。

## 每名可见角色的表演签名

为当前项目中每名可见角色建立以下字段；不需要对白的角色也必须有目标、视线和反应：

| 字段 | 写法 | 不能替代 |
| --- | --- | --- |
| `objective` | 面向具体对象的行动动词，如“逼退守门者”“护住伤员” | “表现愤怒/紧张” |
| `obstacle_stakes` | 当前阻碍与失败代价 | 敌方威胁和空间因果 |
| `tactic` | 试探、压迫、诱导、撤退、保护、换位等策略；失败后要变招 | 招式名称 |
| `performance_beats` | 2–4 个可见变化：姿态、目光、呼吸、速度、距离或手上事务 | 无因特写 |
| `gaze_target` | 眼睛先于头部指向的目标、短暂扫视和重新锁定 | 镜头运动 |
| `body_state` | 重心、开放/收缩、握持、肩颈、呼吸和移动节奏 | 受力结果 |
| `business` | 与目标相关的抓握、擦血、护住伤口、校正武器或数步等身体任务 | 装饰动作 |
| `voice_dialogue` | 声线锁定；对白只使用用户提供的原句 | 临时台词、旁白或即兴词 |
| `hit_reaction` | 受击方向、脚步补偿、回弹、视线保持、疼痛如何改变策略 | “被打飞”空泛描述 |
| `next_action` | 表演变化直接导致攻击、格挡、撤退、能力切换或反制 | 情绪停顿 |

推荐的单 Beat 链为：

`目标/障碍 → 读取威胁 → 临战判断 → 动作选择 → 接触/受击 → 身体与眼神反应 → 战术改变 → end_state`

每个反应必须回答“观众看见了什么”和“它怎样改变下一动作”。反应可以先于对手动作结束出现，例如提前抬眼、收肩、松握或改变脚尖方向；重要消息或重击后保留短暂评估，但不能切断动作连续性。

## 可观察表演规则

- 用呼吸、吞咽、眨眼、微扫视、下颌收紧、重心转移、手上事务和动作中断表达压力，不只写“紧张”“愤怒”“悲伤”。
- 每个习惯性小动作必须有触发器；每个角色面具必须有明确裂口。不要在镜头切换后把情绪重置为中性。
- 眼神必须有搜索、锁定、判断、失焦或重新确认的目标；眼睛可比头部提前极短时间移动，眨眼和 catchlight 保持自然。静止应读作蓄势或判断，不是冻结。
- 强者通常用更少的手势和更稳定的重心施压；例外必须由伤势、地形、关系或策略改变解释。
- 近景减少大幅肢体动作，优先保留眼神、呼吸、握持和一个可读接触结果；特写结束后重新锚定人物、武器、空间、受力方向或战场优势。
- 受击反应必须保持物理可达：写清方向、阻力、重量转移和落定状态。若某个情绪动作不可行，将其能量转移到可行的手、肩、步伐、呼吸或视线行为。
- 多人反应按先后波次传播；未分配角色不得凭空获得台词、目标或新动作。
- 非说话角色嘴唇保持静止；对白必须逐字使用用户提供的句子，不添加即兴台词、字幕或隐藏旁白，除非用户明确要求。
- 声音事件必须与身体事件同步：脚步随接地、金属声随真实碰撞、呼吸随用力和恢复；声音不能掩盖接触不清。

## 与战斗导演的冲突裁决

1. 用户锁定的人物、关系、胜负、动作顺序、对白、时长和结尾优先。
2. 动作接触、受力、位移和平台硬限制优先于表演装饰；表演只能显化判断和后果，不能替代命中或敌方威胁。
3. 每个镜头仍只有一个主要视觉主语和一个主运镜。表演特写必须服务某个动作决策、优势变化或关系转折，不能把战斗变成无因摆拍。
4. 表演层必须沿用前一 Beat 的 `end_state`，并把新的视线、呼吸、姿态、伤势和情绪惯性传给下一 Beat。
5. 角色小传与当前场景行为分开：重复角色可维护 150–220 词英文 master profile，但当前镜头只继承身份、声线、标志性眼神/习惯和情绪连续线，再按距离、姿态、业务和节拍改写；小传不写服装、镜头、颜色或摄影。

## A 稿、B 稿与视频生成边界

- A 稿写完整的 `performance_signature`、目标、阻碍、策略变化、眼神/呼吸/重心、受击后果和关系信息。
- B 稿只保留可观察且能改变动作或镜头的表演 cue；删掉空泛情绪形容词、重复小动作和不服务主视觉的心理解释。
- 需要视频生成时，先把表演层并入完整的 CINEDANCE 风格镜头 Prompt，再按用户明确指定的平台和能力执行。仅说“设计/优化 Prompt”时，不提交付费生成任务。
- FilmOS 的模型选择、创建、等待和下载仍遵循独立 `acting` Skill 的边界；本融合协议不允许用 shell、curl、Python 或其他视频提供方替代 FilmOS，也不因融合自动发起生成。

## 交付前检查

- 每名可见角色有目标、阻碍/筹码、策略、至少两处可见节拍、视线目标和身体状态；
- 每次重要接触或受击都有方向、身体反馈、结果和下一动作；
- 表演变化确实改变攻击、格挡、换位、撤退、能力或优势预期；
- 对白逐字、非说话嘴唇静止，声音和身体事件一致；
- 特写后恢复空间/武器/受力锚点，跨镜头继承伤势、视线、呼吸和情绪惯性；
- 没有用表情、慢动作、声音或镜头运动掩盖缺失的动作因果。
